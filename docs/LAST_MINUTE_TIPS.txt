LAST MINUTE DEFENSE TIPS FOR DOOM PROJECT
=========================================

🎯 30-SECOND PITCH (Memorize this!)
"This is a Doom clone built in C# using Windows Forms that recreates the core 1993 Doom gameplay. It features a working raycasting engine for 3D rendering, enemy AI with multiple types, weapon systems, and wave-based progression - all implemented from scratch without external game engines."

🔑 KEY SYSTEMS TO BE ABLE TO EXPLAIN:
1. Raycasting Engine (Renderer.cs) - "This is how we get 3D from a 2D map"
2. Game Loop (Game.cs) - "How the game runs 60 times per second"
3. Player Movement (Player.cs) - "How you move and shoot"
4. Enemy AI (EnemyAI.cs) - "How enemies chase and attack you"
5. Weapon System (Player.cs) - "The shotgun with spread and animation"
6. HUD System (Hud.cs) - "What you see on screen"

💡 WHEN ASKED "HOW DOES X WORK?"
- Raycasting: "We cast a ray for each screen column (640 rays) from the player's position. Each ray travels until it hits a wall in our map. The distance to that wall determines how tall we draw the wall slice - closer walls appear taller. We also apply texture mapping based on where the ray hit the wall."
- Movement: "We check if moving in X direction would hit a wall, then check Y direction separately. This 'axis separation' lets you slide along walls instead of getting stuck on corners."
- Enemy AI: "Each enemy has a state machine: idle (standing), walk (chasing), attack (swinging), pain (hit reaction), death (dying), and cooldown (between attacks). They use line-of-sight checks to see if they can see you through walls."
- Weapon: "When you click, we spawn 7 pellets with slight random spread. For each pellet, we check if it hits an enemy by seeing if the enemy is along the pellet's path and close enough to the line (using vector math)."
